## 三、视觉兑现（关键发现：标记 ≠ 画面）

| 检查项 | GLM v1 | GLM v2(修复后) | Luna v1 | Luna v2(修复后) |
|---|---|---|---|---|
| 双角色可区分 | ✅ 乌龟绿壳+四肢 | ✅ | ❌ 只有 clawd 变体 | ❌ 仍未解决 |
| 轨迹线 | ❌ 标了 TRACE_PATH 无画面 | ✅ 脚印链+尘土带+预测虚线 | ❌ | 部分（复审仍有异议） |
| 相遇冻结/强调 | ❌ | ✅ 光晕+格旗切换+爱心+表情弧 | ❌ | ❌ |
| 结尾量化总结 | ❌（庆祝画面无数字） | ❌（缺 Δx/刻度/时间轴） | ❌ | ❌ |

**核心结论**：
1. `// PATTERN:` 标记对齐率 1.0 只是"承诺存在"证明——视觉兑现需审查闭环确认。
2. **双模型共同短板 = pattern 的视觉兑现**（轨迹/冻结/总结），且单轮视觉修复
   不能补齐 Luna 缺的角色原语（引擎只有 clawd()，无乌龟绘制词汇）。
3. GLM 对修复指导的响应极强：即使批评 JSON 解析失败只喂了 500 字符原文，
   仍一次性补齐轨迹+强调两大类。
4. 量化总结（数字/刻度/时间轴）两模型两轮都没做——这是纯新增 UI 元素，
   需要进 Pattern Library 作为标准件（SHOW_BEFORE_AFTER 必须带刻度）。

## 四、决策门证据（方案 §4）

判定：**情况 2（差距明显）→ Stage B Motion Skill 蒸馏 + Pattern Library
runtime 化**。理由：
- 分镜层已达标（两模型都能出正确数学分镜）——蒸馏的对象不是分镜能力。
- 代码兑现层系统性缺失——把 TRACE_PATH/FREEZE_EVENT/SHOW_BEFORE_AFTER
  做成**引擎级带参数原语**（模型填参而非手绘），是唯一可闭环路线。
- 新增库需求：**角色原语库**（乌龟等第二角色）——Luna 无法自造。

## 五、Review loop v1 改进清单（v1.1）

1. 批评 JSON 解析失败时，修复调用应携带完整 raw 文本（本次 GLM 只拿到 500 字符）。
2. 视觉批评器对慢速运动有抽帧混叠（把匀速位移读成瞬移）→ 追逐段加 strip 抽样。
3. 批评器会把 8 联格读成"同屏 8 个角色"——prompt 需显式说明"每格是一个时间点"。
4. GLM 端点长生成断连间歇性发生；断连重试已内置，重试时 prompt 缓存全额命中。
