## 一、总原则（全部继承 ISD 实验纪律）

1. **单文件网页**：每个实验一个独立 HTML，静态服务器/本地双击可开，无后端、无依赖、平台无关；挂 8861（与画廊同域）。
2. **三层反馈分列，不合成总分**：观察层（你做了什么）/ 规则建议层（确定性检查，全部标"教学常用值/教学假设"口径）/ 教师判断层（占位留白）。
3. **口径红线与视频课一致**：工程数值四分标注（已核实/教学常用值/教学假设/须核验）；国标只给查核入口；不对真实工程作合规结论；答辩类无合格判定。
4. **视觉语汇与课程片统一**：drawing_desk 双层系统——图纸层墨线黑三阶（粗/中/细＝F'' 线型三岗）＋教学层 figlib 标注（蓝注/ERR 病灶圈/GHOST 残影）；青枫里401 数据全部取冻结包。
5. **导出数据契约** `drw-lab-v1`（对齐 isd-design-v1）：JSON 导出含操作记录、检查结果、教师判断留空字段。

## 七、v0.2 增补：统一提交与文本化输出（客户三项要求，2026-11-13）

> 原设计（第一~六节）全部不变；本节为增量契约，12 卡一律适用。

### 7.1 统一提交组件 `drw-submit-bar`（要求①：明显提交按钮，允许部分提交）

- 每卡页底**常驻固定提交栏**：进度徽标（已完成 n / 总交互项 m）＋醒目「提交实验结果」主按钮，滚动不消失。
- **未完成也可提交**：点击后弹确认层，只提示汇总（"已完成 X 项 / 共 m 项，尚有 Y 项未完成，确认提交？"），**不逐项点名**；学生选「继续作答」或「确认提交」；全部完成时确认层简化为一键提交。（2026-11-13 用户裁定：确认层不逐项点名，只给计数。）
- 实现纪律：lab.yaml 合同新增必填段 `submit_bar`，sol 生成时注入**同一份 JS 模块**（内嵌，保持单文件、零依赖）。QA 门禁新增断言：①提交栏存在且常驻；②部分提交路径可走通，确认层只显示计数不逐项点名；③`window.DRW.submit()` 出口存在且吐出符合 drw-submit-v1 固定 schema 的单 JSON。

### 7.2 结果文本化（要求②：JSON → 人读表述）

- 提交后产出**自包含 HTML 人读报告**：三层反馈全部以叙述文本呈现——观察层（"你做了什么"逐条叙述）/ 规则建议层（逐条叙述，保留"教学常用值/教学假设"口径）/ 教师判断层（留白占位）。学生端不出现裸 JSON。
- 文本模板按引擎组统一句式，每组一套：A 组＝参数与校验叙述（例："视高设为 1500mm（档位 2/3），视平线位置与两灭点校验一致"）；B 组＝点选/判读叙述；C 组＝布局与动线数值叙述；D 组＝清单与闭合校验叙述。
- 机器数据不删：完整 JSON 内嵌报告 HTML 的隐藏 data 块，附 SHA-256 防篡改，供教师端汇总脚本读取——学生看文本，机器读数据。

### 7.3 统一输出接口 `drw-submit-v1`（要求③：统一方法＋统一接口＋统一格式，2026-11-13 用户确认以平台入库为目标）

- **三统一**，12 卡严格一致：
  - **统一方法**：全卡共用同一提交流程 `collect() → renderText() → export()`，注入同一份 JS 模块，各卡只实现 `collect()` 适配器；
  - **统一接口**：页面暴露唯一出口 `window.DRW.submit()`，平台侧只需对接这一个函数/事件（`drw:submit` 自定义事件同步广播），不感知卡内差异；
  - **统一格式**：出口吐出**单一固定 schema 的结构化数据**（JSON）——`{schema:"drw-submit-v1", 课程, 实验, 学生, 时间, 完成度{总项, 已完成}, 分项结果[], 文本报告段[], 校验和}`，字段名、类型、枚举全卡一致，平台数据库可直接按此 schema 建表/解析入库，无需逐卡适配。
- 分项结果 `分项结果[]` 每项固定字段：`{项id, 题型(引擎组枚举A/B/C/D), 状态(完成/未完成), 文本描述, 机器值}`——文本描述供人读展示，机器值供库查询。
- 报告 HTML 与隐藏 JSON 均由这同一份 schema 数据渲染/序列化而来（单一数据源，两视图）。
- 与 `drw-lab-v1` 关系：v1 原字段整体映射进 `分项结果[].机器值`，不推翻原契约。

### 7.5 平台内嵌回传 `COURSE_PRACTICE_SUBMIT`（2026-11-26 平台技术意见落地）

- **场景**：平台用 iframe 嵌卡片。原来学生提交后只有浏览器下载一个 HTML 文件，平台拿不到内容，学生还得手动上传。
- **协议**：卡片 URL 带 `?parentOrigin=https://平台域名` 时，`exportReport()` 先把整份报告 HTML 渲染成字符串 `html`，再向父页面发：
  `window.parent.postMessage({ type: 'COURSE_PRACTICE_SUBMIT', resultHtml: html }, targetOrigin)`
  父页面收到即可入库/预览；本地下载逻辑保留不变（双通道，谁需要谁用）。
- **实现要点**（`labs/_shared/drw_submit.js` → `exportReport()`）：
  - 只渲染一次 `html`，postMessage 与 Blob 共用同一份字符串，避免两个视图不一致；
  - `parentOrigin` 从 `location.search` 取，传给 `postMessage` 作为 targetOrigin（不用 `'*'`，避免报告外泄）；
  - 仅当 `window.parent !== window` 才发（顶层打开时 `parent === self`，发了也是空转）；
  - 整段包 `try/catch`：origin 非法或父页面已卸载时**不影响本地下载**；
  - `window.__DRW_QA__` 早退分支保持在前，QA 跑批不会触发回传。
- **验收**（2026-11-26，Chrome headless + 本地 8899）：
  - A 内嵌带 `parentOrigin`：父页面收到 1 条消息，`resultHtml` 与本地下载 Blob **字节数完全一致**（5.9 KB），含 `data-checksum`；
  - B 内嵌不带 `parentOrigin`：父页面 0 条，下载照常（5.2 KB）；
  - C `file://` 直接打开：无异常、无回传，下载照常（6.1 KB）；
  - 回归 `_qa_submit.py` 12/12 PASS。
- **给平台的说明**：父页面监听 `message` 时请校验 `e.origin` 为本域；`resultHtml` 是自包含 HTML（含内联样式与隐藏 JSON），可直接存库或 `srcdoc` 预览；单份约 5–8 KB。
