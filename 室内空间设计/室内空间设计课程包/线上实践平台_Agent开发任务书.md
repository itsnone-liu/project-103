# 《室内空间设计》教材与线上实践平台 Agent 执行任务书

**版本**：v1.0（2026-10-19）  
**项目性质**：本科环境设计专业课程研发；教材内容、交互实验、学生前端、教师后台与既有教学平台集成。  
**目标交付**：原创教材定稿、教师手册、约60段微课脚本及关联素材、12个实践实验、1个本科综合项目、可嵌入现有平台的前端、可审核的评价记录。  
**现有资源**：配套《室内空间设计_本科教材试编本_v0.1.md》《空间布局实验_可运行.html》供内容起点与交互POC验证；**不要把试编本直接当成合规审定教材**。

## 0. 给主协调 Agent 的首条指令

> 你是环境设计本科教学资源项目的主协调者。先审计现有教材试编稿和单页交互原型，再按本任务书分阶段完成课程内容与可运行线上实验。坚持“教学目的先于动画/工具形式”，只使用可验证、可授权的来源，不照抄既有教材或线上课程。每个章节保留知识点→使用情境→设计判断→实验操作→评价证据的追溯链。所有国家规范数字、材料性能与无障碍要求需单独建立法规复核记录；未核实之前不能声称达标。以一章一实验做试点，通过教学验收再扩展。任何涉及原课程平台账号、数据、接口及部署权限的操作均先读取项目配置，不得猜测。按阶段交付可测试成果及验收报告，而不是只汇报“已完成”。

## 1. 原则和非目标

**原则**

1. 教材是知识内容的主源（Markdown/结构化JSON），视频、测验和实验是不同呈现形式；不得把视频字幕直接当教材正文。
2. 实验让学生发现设计变量、冲突与权衡，而非追求快速建模速度。
3. 尺度与规范：量纲统一用米（m），输入允许毫米显示；严格区分**教学启发式数值**与**强制规范要求**。任何安全/无障碍合规信息必须可追溯到条文和适用条件。
4. 可复现：同一个版本、场地、家具与规则输入应产生一致的自动几何反馈；记录审查规则版本号。
5. 人工保留最终设计评议权。算法不评“好看”“人性化”“消防合规”等无法完整计算的结论。
6. 内容、实验场景、引擎和UI组件解耦：更换视频或题目不需改动3D引擎。
7. 对接现有学习平台优先通过可嵌入路由或有鉴权的iframe；在平台支持时评估LTI 1.3，不能假定所有平台均支持。
8. 图示、照片、模型、材质、案例采取“原创/CC0/明确授权/已确认许可”的资产规则，记录来源与许可证。

**非目标**：自动生产工程施工图；无证据地进行消防规范校验；一开始建大型BIM系统；上来就开发数字孪生级物理模拟；假设所有课程都需要复杂3D；在线全程调用LLM给出分数。

## 2. 课程内容总体框架

**教材模块**：12章，详见试编稿，教学总体按64课内学时设计（32理论+32实践），配套自学另计。

**微课视频**：第一版约60节×5分钟≈300分钟，作为课前或线上导学资源，不能误认为涵盖全部32理论课时。章内5节可按“现象/概念、分析方法、案例剖析、实验导引、典型错误与复盘”组织。总时长不是强制门槛，以内容完整性为先。

**每章标准资源包**：

```text
chapters/04_functional_zoning/
  chapter.md             # 面向学生的理论课文
  instructor.md          # 教学目标、演示步骤、常见误区、评议建议
  examples.json          # 情境、场地数据、图示资产引用
  concept_questions.json # 可自动判定概念题及解析
  lab.yaml               # 实验合同、输入、变量、判定规则、数据格式
  rubric.yaml            # 人工/自动评分项目与占比
  video/01..05.md        # 微课内容说明与脚本，不含侵权素材
  assets/manifest.json   # 来源、作者、许可、生成日期、校验信息
```

每章 `chapter.md` 的目标体量：约4,000–8,000汉字，视知识密度增减；最终教材建议总规模为8–12万字（可由教材编委会调整），其中案例、图解、表格和参考资源比例合理，不用填充字数。

## 3. 十二项线上实验的实现等级

| 实验 | 名称 | 第一版交互 | 二期扩展 | 评议边界 |
|---|---|---|---|---|
| L01 | 观察与问题标注 | 图片/平面点选、文字注记 | 多层空间证据图 | 自动校验字段，教师审查论据 |
| L02 | 人体尺度与动作包络 | 家具矩形、移动包络、多用户切换 | 动态人体动作动画 | 包络不等于规范值 |
| L03 | 任务书编制 | 用户访谈卡、优先级排序 | 分歧情境对话 | 不由LLM独断需求真实性 |
| L04 | 功能分区与布局 | **本轮原型已有**：拖放、旋转、A/B与导出 | 可设置功能邻接图 | 几何数据≠使用体验 |
| L05 | 动线与通达 | 起终点、离散网格路径、障碍 | 人流情境、多路径 | 不能视为消防疏散分析 |
| L06 | 空间围合与视线 | 屏风/隔墙变化、平面视线射线 | Three.js漫游 | 感受由教师与学生解释 |
| L07 | 自然光与照明 | 日夜预设、光源位置示意 | 可验证的光学引擎/服务 | 未校准前只称示意 |
| L08 | 材料与色彩 | 素材卡、二维界面搭配 | PBR三维材质与统一曝光 | 贴图不证明材料性能 |
| L09 | 家具与多情境 | 布局模板一键切换 | 可变家具动画 | 现实维护仍需核查 |
| L10 | 技术/规范意识 | 风险分类和缺陷定位 | 专家审核工作流 | 不输出自动规范通过章 |
| L11 | 设计表达与评议 | A/B版指标、批注与比对 | 同伴匿名评议 | 自动反馈只占合理部分 |

**优先顺序**：首先做 L04 + L05 + L02 的二维几何群组；它们共享数据结构且最容易被教师实际试教。然后做 L01/L03/L10/L11 的低成本教学交互；最后再做高投入的L06/L07/L08三维视觉实验。

## 5. 实验合同（以L04为模板）

```yaml
lab_id: ISD-L04
version: 0.1.0
name: 功能分区与48平方米学习工作室布局
scene:
  width_m: 8.0
  depth_m: 6.0
  entry: { wall: south, x_start_m: 0.42, x_end_m: 1.68 }
  window: { wall: north, x_start_m: 2.8, x_end_m: 5.5 }
  origin: northwest
student_actions: [add, drag, rotate, delete, save_version, compare, export]
teaching_hypotheses:
  near_window_depth_m: 2.6
  entry_buffer: { xmin_m: 0.35, xmax_m: 2.3, ymin_m: 4.65, ymax_m: 6.0 }
  note: 示例条件，非国家或行业规范要求
auto_checks:
  - collision_pair_count
  - out_of_room_count
  - buffer_overlap_count
  - furniture_floor_area_ratio
  - desk_in_window_band_count
  - assignment_required_items
human_review:
  - space_activity_fit
  - user_needs_argument
  - comfort_and_atmosphere
  - accessibility_and_code_review_needs
exports: [project_json, plan_png, comparison_report]
```

**重点**：演示代码中的“自动评分”是可见反馈，不应成为课程正式评分器的规范性证据。正式评分要把每个条件的教学意义、局限和阈值调研记录清楚。

## 6. 分阶段技术架构

```text
已有LMS / 学习平台
   │ 课程路由/账号鉴权/成绩回传（可选LTI 1.3）
   ▼
课程播放器与章节页面（可替换5min视频）
   ├─ 视频：lesson metadata + 资源URL
   ├─ 内容：Markdown/MDX编译版 + 图示
   ├─ 互动题：章节内/课后事件驱动
   ├─ 实验：独立路由 /labs/:labId
   │    ├─ 2D Geometry Core（确定性）
   │    ├─ 3D Preview（按需动态加载）
   │    ├─ Scenario Data / Rules
   │    ├─ Save / Load / Compare / Export
   │    └─ Evaluation Report（几何/教师/自评拆分）
   └─ 学习总结与Q&A（视频段落结束后调用后端LLM，可选）
        │
        ▼
应用后端（课程/作业/版本/成绩/审计）
        │
        └─ 数据库/对象存储（作品版本、批注、视频索引）
```

**建议前端**：React + TypeScript（可按现有学习平台技术栈替换）。二维绘图优先 SVG/Canvas/Konva 并采用统一米制几何模型；三维预览可用 Three.js。**不建议第一期为满足“技术先进”而全量开发BIM**。

**开源复用路线**：先独立验证 `laanlabs/openPlan3D`（MIT）与 `charmlinn/blueprint3d-modern`（核实具体license文件）是否满足可嵌入性、单位、导入导出、扩展、依赖与许可要求。尤其验证是否能对对象修改产生稳定的事件与JSON、是否支持加载教师设定的禁改墙体/门窗。不要直接将未审计项目作为平台核心；复杂二维/三维引擎可以在P2中接入。来源：
- <https://github.com/laanlabs/openPlan3D>
- <https://github.com/charmlinn/blueprint3d-modern>
- <https://threejs.org/>

**已有SOL视频生产体系的接法**：视频按原生产管线批量制作、渲染。平台仅消费 `video_manifest.json`，以章节知识点定位视频与互动点；可以先做视频，后做实验，不需再次渲染所有视频。课堂中的自动暂停题通过播放器按 `cue_seconds` 触发状态机；教师可关闭暂停题用于线下放映。LLM答疑只置于段尾或章节后，避免频繁打断教学。

## 7. 平台集成的三个级别

**Level A — 独立网页（最先验证）**：静态服务器部署，`/course/interior-design/04` 与 `/labs/ISD-L04`，学生项目先存浏览器或手动导出JSON；不依赖用户身份。当前单页实验就处于此级别。

**Level B — 既有LMS嵌入**：按现有平台路由或允许的iframe集成，后端进行用户鉴权、assignment_id关联、存储与成绩回传。严格处理跨源限制、移动端布局与会话过期，不在URL暴露敏感个人数据。用户身份以服务端可验证凭据为准，不能信任前端传来的 `student_id`。

**Level C — 标准协议**：目标LMS支持时采用1EdTech LTI 1.3；AGS用于成绩簿，Deep Linking用于资源嵌入，NRPS按授权获取成员信息。并非每套平台都原生支持，不强行实施。标准参考：<https://www.1edtech.org/standards/lti>。

可选学习行为记录采用 xAPI 风格的 actor/verb/object，但不需在第一期引入完整LRS；尊重学校隐私制度、最小化采集与保存期。xAPI资料：<https://github.com/adlnet/xAPI-Spec>。

## 8. 数据模型（最小可行）

```json
{
  "schemaVersion": "isd-design-v1",
  "courseId": "ISD-COURSE-01",
  "labId": "ISD-L04",
  "projectId": "sample-01",
  "scene": {
    "unit": "m",
    "width": 8,
    "depth": 6,
    "walls": [],
    "openings": []
  },
  "objects": [
    {"id":"d-01","type":"desk","x":2.5,"y":1.1,"rotationDeg":0,"width":1.4,"depth":0.75}
  ],
  "scenarioVersion": "ISD-L04-0.1.0",
  "ruleVersion": "teaching-heuristics-v1",
  "savedAt": "2026-10-19T00:00:00Z"
}
```

坐标和几何契约：`origin=西北角，x向东，y向南，长度用米，角度用度，物件中心点定位`。服务端对数值范围、object ID、模型引用和非法内容做验证；前端绘图中的像素值不能写入原始设计模型。**所有章节/版本必须保留明确单位、来源和版本**。

评价数据至少分三层：`observations`（客观结果）、`heuristic_feedback`（规则建议）、`professional_review`（教师判断），并在UI上分别标识。不要将三者合成无来源“AI专家总分”。

## 9. 三类评价的严格边界

**A. 确定性**：碰撞、几何越界、指定对象数量、任务书字段完整性、是否提交版本、同场景下确定性路径算法输出。验收方式是固定输入JSON+golden输出校验。

**B. 启发式**：靠窗工作位、家具占地率、入口缓冲占位、场景切换难度。阈值应由课程教师签字认可为“课堂示例”，可随版本调整。仅作为问题提示，不能称为法定指标。

**C. 专业判断**：空间体验、文化回应、审美品质、人体舒适、施工可行性、规范是否合规。学生写方案依据，教师审核，LLM只做归纳与反问；不得伪称基于三维渲染得到精确性能。

课程评分的分值、权重、算法版本与人工修改必须审计留存。成绩申诉要能重新打开对应的方案版本和评价规则。

## 11. 阶段划分与验收

### P0 — 内容与技术审计（先做）

- 读完试编本，出课程目标与毕业要求对应矩阵；标记理论空白和待补典型案例。
- 完成示例项目与规范台账：哪些是教学模拟、哪些是已核实事实。
- 检查开源代码许可、维护情况、版本依赖、移动端与导出功能。
- 试运行L04原型，发现至少5个教学问题/交互问题并提出修改。

**验收**：审计报告、教材缺口清单、实验可行性清单、版权与规范风险清单齐备；不以“已经读过”替代书面证据。

### P1 — 先做一章完整样板（核心阶段）

仅建设第4章《功能分区与空间邻接》的**正式教材样章、教师教案、5段微课脚本、4–6个概念题、L04正式二维实验、评议标准、学生作业样例**。讲义必须包含完整的案例数据和关键问题分析，不能只列要点。

**验收**：教师阅读稿完整；学生从教材可独立理解题意并完成实验；两份不同的合法布局得到不同的可解释反馈；A/B版本保存复现；有教师评论入口（P1允许以Markdown评审表替代后端）。

### P2 — 几何实验平台内核

把L04从单页HTML拆为课程前端模块+几何规则内核；完成L02、L05。必须有统一JSON、快照、坐标系、导出、单位换算（单位存储永远米制）、撤销重做。实现自动化测试。

**验收**：固定测试数据能重复运行；不同屏幕尺寸不改变物体真实位置；触摸/鼠标均可拖动；连续路径与碰撞检查有边界用例；浏览器刷新能从保存的项目恢复；不存在因条件分支造成的违规通过。

### P3 — 教材扩充与低成本互动

在第4章样板通过后，按先后依赖扩充第1–3、5、10–11章，随后第6–9章和综合第12章。建设图示、教师答案和章节题库，完善L01/L03/L09/L10/L11；所有章节遵循统一学术和技术规范。

**验收**：12章内容通过教研核查；知识点到题库、视频和实验可追踪；教师无需修改源代码即可调整课程题目和案例参数。

### P4 — 三维空间实验与综合项目

按可行性引入经过技术和许可证审查的三维库，完成围合/视点（L06）、示意光照（L07）、材料与色彩（L08）；统一90㎡项目的跨实验数据与作品包输出。

**验收**：基础2D与3D几何位置一致；相同设计版本可复现；性能可接受；三维贴图版权已核实；灯光与物理性能的模拟精度边界有明显标识。

### P5 — 现有教学平台接线

读取目标平台实际认证、课程列表、作业、成绩与静态资源接口。开发与视频段落关联的实验入口和课后总结模块。按学校实际条件选择内嵌或LTI。

**验收**：教师可发布、学生可完成、刷新/重连后可恢复、教师能查看对应版本、可导出成绩和作品、学生数据访问控制经检查。

### P6 — 小班教学试点与冻结

邀请教师和学生进行真实课前使用性测试：无提示完成率、交互错误、学习目标达成证据、批改工作量及无障碍问题。记录修改、最后冻结教材版本与代码版本。

**验收**：教材主编、技术负责人、课程负责人三方签核；未确认的规范和素材版权问题不得混入出版版。

## 12. 强制质量门禁与测试清单

**教材门禁**
- 每节内容都有真实教学目标、概念解释、至少一处可操作的应用场景。
- 不允许“AI总结式空洞教材”：如仅说“空间很重要”，缺少条件、过程与例子。
- 所有图示有制作说明；引用案例有来源与授权；不复制整章现成教材。
- 两处以上涉及不同价值判断的设计取舍；不能把美学等非确定性问题改造成唯一标准答案。
- 规范名称、版本和适用条件得到核验；教学假设清楚标注。

**引擎门禁**
- 零输入、非法数值、墙外拖拽、墙体不可编辑、物件重叠、临界接触、旋转后尺寸互换。
- A/B快照不随当前操作被原地修改；导出→导入结果等价；不同像素缩放无单位漂移。
- 场景删除对象后选择状态清空；数据schema升级有迁移说明。
- 网格路径算法必须说明网格尺度对结果的影响；不能输出“不符合国家消防规范”的误导结论。
- 无浏览器内置权限也可阅读理论内容；对依赖WebGL的三维实验提供降级路径。

**教学平台门禁**
- 非本人不能读取他人的方案；分数回传与项目版本绑定；课程权限、成绩和文件下载有后端核验。
- 长视频播放与互动暂停不产生重复记录；无网络时提供合理的保存/失败提示。
- 题库与音视频版权、学习隐私和可访问性留有审计记录。

## 15. 收束建议

不要先把12章微课和12个实验全部建完再试教。**正确的最小闭环是“第4章知识教材 + 5段微课 + 1个真实可操作的布局实验 + 1份学生成果 + 1次教师评议”**。这套闭环能证明教学设计与交互系统互相支持之后，再把同一资源结构扩展至完整课程。

真正成功的标志不是炫酷的模型，而是学生能够回答：“我为什么这样组织空间？哪一个使用者因此获益？我有什么证据？如果条件改变，我要怎样重新设计？”
