# Application Flow & Events Spike 01 — Review

## 为什么选择当前视觉表达

本题最重要的不是空间几何，而是四个同步变化的表示：

1. 水池中的实际水量；
2. A、B、C 三根管的开关状态；
3. 当前净流量的加减合成；
4. 水量—时间图像及其斜率。

因此选择了自包含 HTML + SVG + vanilla JavaScript，但不是因为预设“必须用 SVG”，而是因为 SVG 很适合把水池液面、开关状态、加减流量卡片和分段折线放在同一页面中，并允许时间滑块统一驱动。页面同时提供 Play、时间 slider 和事件跳转。

## 动态表现的数学关系

每一帧由同一个 `stateAt(t)` 计算：

- 当前打开的管道；
- 净流量；
- 当前水量；
- 所处事件阶段；
- 图像上的时间光标和水量点。

动态页面重点表达：

- `净流量 = 所有打开的进水流量 − 所有打开的出水流量`；
- 水量曲线的斜率就是净流量；
- 开关事件使斜率立即改变，但水量本身保持连续，不会跳跃；
- 条件事件“第一次达到 420 L”必须和定时事件“6 分钟后打开 C”按同一时刻统一处理。

## 动画比静态解题额外提供的理解

静态解答容易让学生只记住分段公式。交互页面让学生来回穿过事件时刻，直接看到：

- t=6 前，A+B 使水量以 `+50 L/min` 快速上升；
- t=6 时，水量恰好到达 420 L，因此 C 打开和 B 关闭同时发生；
- 开关同时改变后，净流量从 `+50` 变成 `−5`，折线由上升立即转为下降；
- 折点没有纵向跳跃，说明事件改变的是变化率，不是瞬间改变水量；
- 最大水量正好出现在斜率由正变负的事件点。

### 发现的关键问题

首次实现错误地把事件理解为顺序发生：先在 t=6 打开 C，继续让 B 保持打开，直到 t=14 才关闭 B。这样产生了错误的三阶段模型：

- 0–6：`+50`；
- 6–14：`+15`；
- 14 后：`−5`。

浏览器扫描暴露出的错误结果是：最大水量 540 L（t=14），并且在页面时间范围内无法下降到 300 L。

题意要求“当池中水量第一次达到 420 L 时关闭 B”。而在第一个阶段：

`120 + 50×6 = 420`。

所以 t=6 恰好同时触发两个事件：C 打开、B 关闭。首次实现虽然在隐藏的解析文字里意识到了这一点，但页面的实际状态机、曲线、事件按钮和答案标题仍使用错误时序，构成严重的数学与教学不一致。

视觉上，错误状态机还导致 t=14 截图中的流量合成卡片仍把关闭的 B 以 `+20` 参与加法，进一步误导学生。

## 唯一一轮集中 repair

`index.html` 从冻结的 attempt 复制后，一次性修复：

1. 将事件状态机改为两阶段：
   - `0≤t<6`：A、B 开，C 关，净流量 `+50`；
   - `t≥6`：A 开，B 关，C 开，净流量 `−5`。
2. 将 t=6 标为同一时刻的联合事件：“C 打开 + B 关闭”。
3. 删除错误的 t=14 事件和中间 `+15` 阶段。
4. 将到达 300 L 的事件改为 t=30。
5. 重建分段折线、斜率标签、事件跳转按钮和答案区域。
6. 使关闭的管道在水池图与流量合成卡片中同步变淡，并明确显示“关闭 / 0”。

未引入 capability、parser、Scene IR 或外部依赖。

## 最终数学结论

- B 在 `t=6 min` 关闭；
- 最大水量为 `420 L`；
- 此后在 `t=30 min` 水量下降到 `300 L`。

分段关系：

- `V(t)=120+50t`，`0≤t≤6`；
- `V(t)=420−5(t−6)`，`t≥6`。
